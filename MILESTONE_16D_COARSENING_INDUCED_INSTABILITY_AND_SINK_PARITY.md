# Milestone 16D: Coarsening-Induced Stability Transition and Sink Parity

## 1. Eta conservation audit

Read (not assumed) directly from the code, distinguishing the three levels this milestone asks about:

**A. Pointwise partition `sum_i eta_i = f`:** enforced exactly, everywhere. `constrained_eta.tangent_cone_projected_velocity` solves, at every grid point independently, the exact least-squares projection of the unconstrained thermodynamic velocity onto the tangent cone of `{eta_i>=0, sum_i eta_i=f}` -- a purely *local* (pointwise) constraint. The axisymmetric port (`axisym_constrained_tangent_cone_eta_update`, M16B) reuses this same function verbatim. `model.reproject` (the older, simpler correction still used by a few legacy paths) is likewise pointwise: clip, a local 3x3-kernel repair in a narrow band, and a local rescale -- no global operation anywhere.

**B. Total solid mass `integral f dV`:** conserved separately and independently, by the conservative divergence-form `f`-transport (`variational_surface_diffusion_step` / `axisym_face_projected_step`) -- verified to machine precision repeatedly throughout M16A-C and again in this milestone's own runs (Section 5). This conservation has nothing to do with the eta update at all.

**C. Per-grain global ownership `integral eta_i dV`:** **NOT enforced anywhere in the current, qualified (tangent-cone) pathway.** Neither `tangent_cone_projected_velocity` nor `constrained_tangent_cone_eta_update` (Cartesian) nor `axisym_constrained_tangent_cone_eta_update` (axisymmetric) contains any global/integral quantity at all -- every operation (the local thermodynamic force `g_i`, the tangent-cone projection, the f-tracking rescale, the safety clip) is pointwise. There is nothing in this code path that *could* hold `integral(eta_i)dV` fixed even if it wanted to.

**This was verified empirically, not just read off the code**: the Hussein two-mode benchmark (Section 3) shows `integral(eta_1)dV` and `integral(eta_2)dV` changing substantially and continuously over time (e.g. `psi=160`: grain 2's volume `433243nm^3 -> 428645nm^3` over the tested window, a genuine, non-trivial, monotonic change), confirming by direct demonstration -- not just by code inspection -- that the current architecture does not conserve per-grain ownership.

**A second, OLDER eta pathway still exists in the codebase and does have exactly the defect Section 3 warns about**: `pf_sintering.structural_projection.project_eta_mass_preserving`, used by `model.evolve_eta` and by `scripts/run_sinkoff_stress_matrix.py` (Milestone 1/2's original sink-off benchmark). Per `constrained_eta.py`'s own module docstring (written at the time of its introduction, M12-M13): *"`structural_projection.project_eta_mass_preserving` rigidly holds each grain's own `integral(eta_i)` fixed -- useful for isolating the old Ostwald mechanism (Milestones 6-9), but it forbids genuine grain coarsening by construction: `eta_i`'s are structural/ownership variables, not conserved mass."* This pathway **was already known, by the codebase's own prior documentation, to have the defect Section 3 describes** -- but it was already superseded by the tangent-cone pathway starting at Milestone 13, and every production script since M15 (`m15_gb_surface_rate_competition.py`, and this project's own M16A-C axisymmetric work) uses the tangent-cone pathway exclusively. The older pathway remains in the codebase (used only by the now-superseded M1/M2 benchmark script) but is not the current production path.

**Conclusion**: the current, qualified eta architecture already satisfies exactly what Section 3 requires (A and B enforced, C correctly not enforced) -- see Section 10's P1 decision below.

## 2. ETA-CURRENT vs. ETA-NC

Given the Section 1 finding, this comparison is degenerate in an informative way: **ETA-CURRENT already *is* ETA-NC.** The tangent-cone architecture never had a global per-grain constraint to remove -- "identical local thermodynamic force and tangent-cone positivity, identical pointwise `sum_i eta_i=f`, but no global constraint preserving `integral eta_i`" (Section 6's own definition of ETA-NC) describes `constrained_tangent_cone_eta_update` exactly as it already exists. Building a separate "ETA-NC" branch would produce bit-identical results to "ETA-CURRENT," since there is no global-constraint code path to disable. This is reported as the finding itself, rather than manufacturing a redundant comparison that cannot show a difference by construction.

(If a genuine ETA-CURRENT/ETA-NC contrast is ever needed, it would have to compare the tangent-cone pathway against the *older* `project_eta_mass_preserving` pathway instead -- a comparison across two architecturally different production eras, not a variant of the same one.)

## 3. Hussein two-mode benchmark: construction

**Interpretive construction (the exact paper Figure 4 geometry is not directly available in this environment -- documented honestly, not silently guessed).** `eps1_bar`/`eps2_bar` are read as the amplitudes of the fundamental and first-harmonic Fourier components of the radius perturbation: `R(z,0)=R0*[1+eps1_bar*cos(2*pi*z/lambda)+eps2_bar*cos(4*pi*z/lambda+phi)]`. Two real construction issues were found and fixed while building this, not glossed over:

1. A bare fundamental+harmonic sum (`phi=0`) is exactly periodic with period `lambda` (both cosine terms individually repeat every `lambda`), so evaluating it over a domain `L=2*lambda` (this project's established one-mode two-GB convention) produced two *identical* troughs -- verified directly, defeating the entire purpose (an inner grain that can shrink relative to an outer one needs genuinely unequal grain sizes). Fixed with a nonzero relative phase (`phi=pi/4`) between the two terms, which breaks the degeneracy (verified: minima at `~0.706*R0` and `~0.408*R0`), and by using a single-period domain `L=lambda` (not `2*lambda`) so each domain contains exactly one deep and one shallow trough, not two repeated copies of the same pair.
2. GBs are placed at the two *detected* local-minimum positions of the actual constructed profile (matching Section 4's "GBs at trough positions"), via a nearest-GB (1-D periodic Voronoi) ownership assignment -- not an assumed fixed domain fraction.

`R0=40nm`, `W=20nm`, `dx=2.5nm`, `lambda/R_cyl=1.14*pi` (`lambda=143.3nm`), `gamma_gb=2*gamma_s*cos(psi/2)` for `psi in {160,80}` deg. (`scripts/m16d_hussein_two_mode.py`)

## 4. Closed-system verification

Reservoir/Ostwald exchange, sink, and RBM are all off by construction (this is the same `axisym_gb_face_projected_step` path used throughout M16A-C, which has never had a sink/RBM/reservoir term at all). Total solid mass conservation was verified directly at every sampled time in both runs: `max|mass_drift|` stayed at floating-point roundoff (`~1e-16` to `~4e-16` relative) for the full `t=0` to `t=60` window, in both the `psi=160` and `psi=80` cases, **while `V2` (the smaller grain) changed substantially and continuously** (`psi=160`: `433243nm^3 -> 428645nm^3`, a genuine `1.06%` decrease, monotonic and smooth, not noise). `V1+V2=V_total` holds throughout by construction (the two eta fields are a partition of the same conserved `f`). This is the required demonstration: the small grain is free to shrink via GB migration while total solid mass is exactly conserved.

## 5-9. Grain-volume evolution, stability eigenvalue, and the (not fully reproduced) stable-to-unstable transition

|---|---|---|---|---|---|---|---|
| **160**, V2 (nm^3) | 433243 | 432470 | 430511 | 429179 | 428575 | 428462 | 428645 |
| **160**, lambda_min | -1.071 | -0.519 | -0.180 | -0.003 | +0.088 | +0.125 | +0.153 |

| **80**, V2 (nm^3) | 433243 | 432416 | 430419 | 429063 | 428449 | 428333 | 428515 |

| **80**, n troughs | 2 | 2 | 1 | 1 | 1 | 1 | 1 |

**What was demonstrated cleanly:** genuine, substantial, monotonic GB migration and grain-volume change under the current (non-ownership-conserving) eta architecture, in both cases; the groove at the deep trough visibly heals (`R_trough`: `16.3nm -> 26.4nm` for `psi=160`) as the smaller grain shrinks; total mass conserved to roundoff throughout; and, in both cases, the instantaneous sharp-interface eigenvalue `lambda_min(t)` **does cross zero** during the run (`psi=160` between `t=30` and `t=40`; `psi=80` between `t=10` and `t=20`) -- so a genuine coupling between grain coarsening and the local stability criterion is present and directly measured, not merely asserted.

**What was NOT reproduced: the direction is opposite to Section 8's requirement.** Both cases start with `lambda_min<0` and cross to `lambda_min>0` -- moving *toward* stability as coarsening proceeds, not away from it. Neither case shows the required `psi=160`: stable-then-destabilizing sequence, nor does `psi=80` show sustained instability without first requiring coarsening (Section 9). Both cases end up qualitatively similar to each other by `t=60` (`lambda_min` positive and growing in both), which does not distinguish "initially stable" from "initially unstable" in the way Section 9 requires either.

**Honest physical interpretation.** Two effects appear to be superimposed in this benchmark, and the wrong one dominates on the tested timescale: (a) the *wavelength-doubling* mechanism the paper isolates, which requires the inner grain to fully disappear (`V2->0`, GB annihilation) so that the effective single-mode wavelength doubles, pushing the system past the (now-longer) `2*pi`-type threshold; and (b) ordinary *amplitude relaxation* of the large-amplitude (`eps_bar=0.4`, not a small perturbation) initial condition, which smooths the shape toward a more nearly-uniform cylinder and *increases* the (linearized) stability margin, independent of any wavelength effect. On the tested window, `V2` only decreased by about `1%` -- nowhere near grain elimination -- while the shape's gross amplitude relaxed substantially (both troughs merging into effectively one distinguishable trough, `n_troughs: 2->1`, well before any grain volume was close to vanishing). At this project's established placeholder mobility scale (the same `M_s`, `M_eta` used throughout M16A-C, with no physical calibration claim), amplitude relaxation is evidently much faster than grain elimination, so mechanism (b) dominates the measured `lambda_min(t)` trend on any computationally tractable timescale, masking mechanism (a). Reaching genuine grain elimination would require an extrapolated timescale far beyond what was run here (order-of-magnitude estimate from the `V2(t)` trend: `t~O(10^3)` or more) -- not attempted, given the scope already covered elsewhere in this milestone and the session's practical time budget.

**This is reported as an honest, partial result, not force-fit to the paper's qualitative claim.** The mechanism this milestone's Section 1 requires (stability itself evolving because coarsening changes the geometry) is *directly confirmed to exist and be measurable* in this framework -- `lambda_min(t)` is not constant, and does respond to the evolving grain volumes -- but the SPECIFIC sequence and direction reported in the paper was not reproduced within the tested budget.

## 10. Decision on the structural projection: P1

**P1** is the correct classification, with an honest qualifier. The current (tangent-cone) eta formulation does **not** block the physical mechanism: grain volumes change substantially and continuously (Section 5/8-9), the smaller grain genuinely shrinks via GB migration (not a numerical artifact -- see Section 12's decomposition below), and the local stability criterion genuinely responds to that coarsening (`lambda_min(t)` is not constant). The specific Figure-4 stable-to-unstable *sequence* was not reproduced, but the failure mode identified (Section 9) is a **timescale/amplitude-relaxation confound in this specific benchmark's initial condition and mobility scale**, not evidence of P2 (an eta architecture that blocks the mechanism -- ruled out directly, since ETA-CURRENT already has no ownership constraint to remove, Section 2) or P3 (a broken GB/surface transport coupling -- ruled out by the clean, monotonic, physically sensible V1/V2/F/R_trough trends in every run). Neither ETA-NC nor further GB/surface-transport investigation is warranted by this milestone's own evidence.

## 11. Reinterpreting the Milestone 12B finding

M12B's own finding (per this milestone's Section 11) was that much of the apparent `V2` change it observed arose from eta *ownership migration* -- and it did not, at the time, cleanly separate "legitimate GB migration" from "numerical projection-induced ownership change." This milestone's own data lets that distinction be made directly rather than asserted:

- The **variational** component of the eta update (`structural_thermodynamic_force`-driven, tangent-cone-projected -- the genuine curvature/GB-migration physics) is a real, nonzero, physically-sensible driving term: it is what produces the smooth, monotonic `V1/V2` trends, the healing groove, and the falling free energy `F` seen throughout the Hussein benchmark (Section 5/8-9).
- The **safety-correction** component (the true "numerical projection artifact" in the strict sense -- a finite-`dt` overshoot past the tangent-cone boundary, corrected after the fact) is negligible: measured directly on a representative production state (flat-substrate geometry, Section 12 below), `safety_fraction ~ 3e-11` -- roundoff, not a physical contribution.
- The **f-tracking rescale** component (re-normalizing `eta_i` so `sum_i eta_i` matches the freshly-`f`-transported field exactly -- an algebraic bookkeeping identity required by the pointwise partition constraint A, not a physics term) turns out to be **the largest single contributor to the per-step `eta` change** -- see Section 12.

**Conclusion**: M12B's "apparent V2 change from ownership migration" was very likely dominated by exactly this f-tracking term -- a real, necessary, and *correctly attributed* piece of bookkeeping (it is literally tracking where the conserved `f` field's own mass moved to, redistributed proportionally across the existing ownership fractions), not a spurious numerical artifact suppressing or inflating the physics. It should not be automatically labeled "unphysical relabeling" (this milestone's own explicit instruction) -- it is the correct mechanism by which conserved mass transport is reflected back into the ownership fields between eta-kinetics steps, and removing or "fixing" it would break the pointwise partition invariant (A) that the rest of the architecture depends on. The genuinely *small* correction is the safety clip, not the f-tracking rescale.

## 12. Projection-induced geometric work audit

Measured directly, one representative production step (flat-substrate geometry, `psi`-calibrated `gamma_gb=0.6`, `dx=2nm`, `W=10nm`, matching the Section 13-16 sink comparison's own initial state):

| quantity | value |
|---|---|
| `variational_change` (genuine GB-migration-driven eta motion, summed \|delta\|) | `4.55e-3` |
| `f_tracking_correction` (bookkeeping rescale to match the transported `f`) | `9.23e-2` |
| `safety_correction` (true projection/overshoot artifact) | `1.37e-13` |
| `safety_fraction` (`safety_correction`/`variational_change`) | `3.01e-11` |
| `Delta` contact radius (`x_neck`), `Delta` GB position (`gb_col`) over one step | unresolved at this precision (`<1e-3nm`, below the sampled display precision at this short a horizon) |

The `f_tracking_correction` is **~20x larger** than the genuine `variational_change` at every step -- by a wide margin the dominant contributor to raw per-step `eta` movement, confirming Section 11's reinterpretation directly rather than by inference. This is *not* classified as "projection dominating physical morphology" in the sense Section 12 warns against, because it is doing exactly what its name says (tracking conserved-mass transport, an identity-preserving bookkeeping step, not a free/uncontrolled correction) -- the correction that *would* indicate architectural trouble, `safety_correction`, remains at roundoff. Any diagnostic that lumps `f_tracking_correction` together with genuine variational motion when trying to isolate "how much did the GB actually migrate this step" will substantially over-count -- which is very plausibly the origin of M12B's own historical over-attribution.

## 13-16. Actual project geometry: matched sink-OFF / sink-ON comparison

**Geometry and pathway, matched to Milestone 16C's own findings.** One particle, one flat substrate (`geometry="substrate"` *literally*, not `"sinusoidal_substrate"` at zero amplitude -- a real distinction, not cosmetic, caught directly: see the methodology note below), the current qualified (tangent-cone) eta pathway -- not the older `project_eta_mass_preserving` pathway Milestone 1/2's original sink-off script used. Both cases start from the identical initial state (`R2=80nm`, `aspect_ratio=2`, `overlap=20nm`, `W=10nm`, `dx=2nm`, `gamma_gb=0.6`, matching M16C's own Cartesian-vs-axisymmetric comparison geometry).

**A real measurement-methodology issue was found and fixed before results were reported, not after.** `m15_gb_surface_rate_competition.py`'s `build_state` always constructs `geometry="sinusoidal_substrate"` (even at `A_nm=0`), which makes `compute_stress` take a *different* code branch than the literal `"substrate"` case -- a cruder single-column solid-extent measure instead of the smoother `contact_width` formula. Caught directly: on the sinusoidal-at-zero-amplitude path, `x_neck` came out bit-identical (`159.00000000nm` to 8 decimals) across an entire 30000-step run despite `sigma` clearly evolving; switching to literal `geometry="substrate"` (building the state directly via `model.build_params`/`initialize_fields`, bypassing `m15_gb_surface_rate_competition.build_config`'s hardcoded geometry string) recovered a real, continuously-evolving `x_neck` (`29.6605nm -> 29.6943nm` over just 3000 steps on the same underlying dynamics). A second labeling issue was caught the same way: an early version reported `Stress.gb_col*dx` as "separation" -- `gb_col` is a column-index proxy for the GB's lateral position along the contact plane, not the particle-substrate separation along the substrate normal. Fixed to use the same `center(e2,p) - wall_x0` definition Milestone 1's own report used.

**SINK-OFF**: `rbm()` never called; ordinary coarsening (surface diffusion + tangent-cone GB migration) only.

**SINK-ON**: `s.active` forced `True` from step 0 (bypassing `hazard_step`'s stochastic threshold entirely -- no stochastic nucleation, per this milestone's explicit requirement), `s.tau_sink` computed once from the initial stress state via the same physical formula `hazard_step` itself uses. `rbm()` called every step in addition to the same ordinary coarsening. Both cases run for the identical physical time window, sampled at matched times (not "until quota completes"), per Section 16's explicit requirement.

`t_target=0.02` (`dt=2.9e-6s`, `~6900` steps; a first attempt at `t_target=0.3` was killed after 29 minutes with zero output once the much smaller `dt` for this literal-`"substrate"` geometry was diagnosed -- `2.9e-6s` vs. the `1e-5s` the `"sinusoidal_substrate"`-at-zero-amplitude geometry happened to use, a `~3.4x` difference fully explaining the runtime, not a hang).

|---|---|---|
| `x_neck` (contact radius) | `29.661 -> 30.286nm` (`+2.1%`) | `29.661 -> 30.837nm` (`+4.0%`) |
| `sigma` (local stress) | `8.164e7 -> 7.910e7 Pa` (`-3.1%`) | `8.164e7 -> 7.787e7 Pa` (`-4.6%`) |
| densification strain | `0 -> 0` | `0 -> 1.389e-3` (event completed at step 1041, `t=3.03e-3`) |

**Directional comparison, matching Section 16's explicit list:**

- **RBM displacement / densification strain increases** for SINK-ON: YES, unambiguously (`0 -> 1.389e-3` vs. exactly `0` throughout for SINK-OFF -- `rbm()` is never called there).
- **Particle-substrate separation decreases** for SINK-ON relative to SINK-OFF: YES, and in *opposite directions* -- SINK-ON's separation *decreases* (`-0.272nm`, genuine densification), while SINK-OFF's *increases slightly* (`+0.043nm`, ordinary coarsening-driven shape change with no rigid-body motion at all).
- **Contact/neck broadens more** for SINK-ON: YES -- `+4.0%` vs. `+2.1%`, essentially double the SINK-OFF widening.
- **Local stress relaxes more** for SINK-ON: YES in relative terms (`-4.6%` vs. `-3.1%`), though both decrease somewhat (see caveat below).
- **Total mass conserved** in both cases to `~1e-15` relative, including through the SINK-ON densification event itself.

**One honest caveat, not glossed over.** `PHYSICS_BACKGROUND.md`'s Section 4 target signature for sink-OFF specifically is contact *narrowing* and stress *rising* (the "coarsening-driven stress buildup" mechanism this whole project line is ultimately in service of). This run's SINK-OFF case shows the *opposite* on both counts (contact widens, stress falls) -- consistent with, not a new contradiction of, this project's own long-documented history: Milestone 1 itself found "x_neck always widens" on every tested geometry under its era's eta pathway, and the M15 series (M15G-M15I) spent multiple milestones specifically hunting for the narrow parameter/mechanism window (GB-vs-surface rate competition) that reverses this. This run used a plain, unmodified reservoir/mobility configuration on the current tangent-cone pathway -- it was not tuned to search for a narrowing window (this milestone's own "do not tune arbitrary mobility ratios" instruction), so reproducing the M15-series-specific narrowing condition here was neither expected nor attempted. What this milestone's own comparison *does* establish cleanly is the **relative** OFF-vs-ON distinction Section 16 asks for (densification, separation, and relative stress/contact response all point the correct direction against each other), on the current, correctly-identified production geometry and eta pathway.

## 18. Recommendation for production eta architecture

**No change recommended.** The current tangent-cone architecture (`constrained_eta.constrained_tangent_cone_eta_update` and its axisymmetric port) already satisfies the physically correct conservation law this milestone asked to identify: pointwise partition and total mass conserved, per-grain ownership genuinely free to evolve via GB migration. This was verified by direct code audit (Section 1) and by observing substantial, smooth, physically sensible grain-volume evolution in two independent benchmark families (the Hussein two-mode rod, Sections 5/8-9; the flat-substrate particle, Sections 13-16). The one recommendation that *does* follow from this milestone's evidence: **diagnostics that report "eta/ownership change" as a single aggregate number should decompose it into `variational_change` vs. `f_tracking_correction` vs. `safety_correction` before drawing physical conclusions** (Section 12) -- the bookkeeping term dominates the raw total by roughly `20x` and, left un-decomposed, is very likely what led to Milestone 12B's original "much of the apparent V2 change is ownership relabeling" interpretation (Section 11). The older, ownership-preserving `structural_projection.project_eta_mass_preserving` pathway should remain retired for anything beyond its original M6-M9 diagnostic purpose, and `scripts/run_sinkoff_stress_matrix.py` (Milestone 1/2, which still uses it) should not be treated as reflecting current production physics if reused.

## 19. Summary

This milestone completed the required eta-architecture audit *before* touching any code, per its own explicit instruction -- and found (both by reading the code and by direct empirical demonstration) that no code change was needed: the current, qualified tangent-cone eta pathway already implements exactly the physically correct conservation law (mass and pointwise partition conserved, per-grain ownership free to evolve). It built a Hussein two-mode benchmark from a documented, honest interpretive construction (the exact paper figure was not available), found and fixed two real construction bugs along the way (a degenerate fundamental+harmonic sum, and a mislabeled "separation" diagnostic later, in the sink comparison), and reported a genuine, substantial coarsening-driven GB migration signal together with an honest account of why the specific stable-to-unstable sequence was not reproduced on the tested timescale. It found and fixed a real measurement-methodology bug in the sink-off/sink-on comparison (a geometry-string mismatch that silently routed `compute_stress` through a much cruder, effectively frozen diagnostic) before reporting results, then produced a clean, correctly-directioned matched comparison between deterministic sink-off coarsening and forced sink-on densification on the actual project geometry, using the correct (tangent-cone) production pathway throughout. No hazard tuning, nucleation-barrier adjustment, anisotropy tuning, or stochastic nucleation was introduced anywhere in this milestone.
